# BUSINESS KEY — نسخه چندکاربره (MVP اجرایی)

این بسته علاوه بر موتور کوچ و دریافت داده‌های بیرونی، ثبت‌نام و ورود کاربران، پایگاه داده SQLite، فضای داده مجزای هر حساب، پنل مدیریت کاربران، تعیین پلن اشتراک، تعلیق حساب و خروجی CSV را اضافه می‌کند. این نسخه MVP است و برای انتشار عمومی هنوز به درگاه پرداخت، HTTPS، محدودیت نرخ، سیاست حریم خصوصی و آزمون امنیتی نیاز دارد.

## نکته شفاف درباره وضعیت اتصال

این بسته از نظر کدنویسی آماده اجراست، اما بدون کلید API معتبر و URL منابع خبری/اقتصادی، اتصال بیرونی فعال نمی‌شود. هیچ نرخ تورم، ارز یا خبر زنده‌ای جعل نشده است. در حال حاضر منابع خبری به انتخاب مالک سرویس از طریق `NEWS_FEEDS` تنظیم می‌شوند؛ شاخص‌های رسمی اقتصادی نیز به منبع داده‌ای نیاز دارند که دسترسی و مجوز استفاده از آن مشخص باشد.

## اجرای محلی

1. Python 3.10 یا جدیدتر نصب کنید.
2. در پوشه پروژه ترمینال باز کنید و اجرا کنید:

   ```bash
   python -m venv .venv
   # Windows:
   .venv\\Scripts\\activate
   # macOS/Linux:
   source .venv/bin/activate
   pip install -r requirements.txt
   ```

3. فایل `.env.example` را به `.env` کپی کنید. حتماً `SECRET_KEY`، `ADMIN_EMAIL` و `ADMIN_PASSWORD` را با مقادیر قوی و مخصوص خودتان جایگزین کنید. حساب مدیر در اولین اجرای برنامه ساخته می‌شود؛ اگر دیتابیس از قبل وجود داشته باشد، مدیر جدید خودکار ساخته نمی‌شود.
4. اجرا:

   ```bash
   python app.py
   ```

   برای اجرای مناسب‌تر با Waitress: `python -m waitress --listen=127.0.0.1:8000 app:app`

5. مرورگر را در `http://127.0.0.1:8000` باز کنید. ابتدا با ایمیل و رمز مدیر وارد شوید؛ سپس کاربران می‌توانند از صفحه ورود ثبت‌نام کنند.

## تنظیمات اتصال

- `OPENAI_API_KEY`: کلید خصوصی API ارائه‌دهنده مدل. کلید را در چت، فایل HTML یا مخزن عمومی قرار ندهید.
- `OPENAI_BASE_URL`: آدرس پایه API سازگار با OpenAI.
- `OPENAI_MODEL`: نام مدل در حساب ارائه‌دهنده شما.
- `NEWS_FEEDS`: فهرست URL خوراک‌های RSS/Atom معتبر و مجاز، جداشده با کاما.
- `ECONOMIC_DATA_URL`: آدرس endpointای که JSON شاخص‌های اقتصادی را برمی‌گرداند.

## قابلیت‌های حساب و مدیریت

- ثبت‌نام و ورود با ایمیل و گذرواژه هش‌شده
- نشست امن مبتنی بر Cookie و جداسازی اطلاعات هر کاربر در SQLite
- پنل مدیر: مشاهده کاربران، تغییر نقش، پلن `free / pro / enterprise` و وضعیت فعال/تعلیق
- خروجی CSV از پروفایل، اهداف و رقبا برای هر حساب
- سه پلن در رابط کاربری تعریف شده‌اند؛ فعال‌سازی پلن پولی فعلاً دستی و از پنل مدیر است. درگاه پرداخت آنلاین متصل نیست.

## APIها

- `POST /api/auth/register` و `POST /api/auth/login` ثبت‌نام و ورود
- `POST /api/auth/logout` و `GET /api/auth/me` نشست کاربر
- `GET/PUT /api/account/data` داده‌های اختصاصی حساب
- `GET /api/account/report.csv` خروجی اطلاعات حساب
- `GET /api/admin/users` و `PATCH /api/admin/users/<id>` مدیریت کاربران (مدیر)
- `GET /api/admin/summary` آمار پنل مدیریت
- `GET /api/health` وضعیت پیکربندی سرویس‌ها
- `POST /api/coach` بدنه: `{"question":"...","profile":{...},"history":[]}`
- `GET /api/news` دریافت آیتم‌های RSS/Atom
- `GET /api/economic-indicators` دریافت JSON شاخص‌های اقتصادی از منبع پیکربندی‌شده

## پیش از انتشار عمومی (ضروری)

این نسخه هنوز محصول SaaS آماده بهره‌برداری عمومی نیست. پیش از انتشار باید درگاه پرداخت و تمدید/انقضای اشتراک، تأیید ایمیل و بازیابی گذرواژه، محدودیت نرخ درخواست و مقابله با ثبت‌نام رباتی، محافظت CSRF متناسب با دامنه نهایی، پشتیبان‌گیری و بازیابی پایگاه داده، ثبت رویداد مدیریتی، سیاست حریم خصوصی و شرایط استفاده، مانیتورینگ، دامنه و HTTPS، و آزمون امنیتی مستقل اضافه و آزمایش شوند. برای کاربران داخل ایران، دسترسی شبکه به ارائه‌دهنده API خارجی و شرایط سرویس باید جداگانه بررسی شود.

## امنیت

فایل `.env` را منتشر نکنید. `SECRET_KEY` و رمز مدیر را روی سرور با مقادیر تصادفی و قوی تنظیم کنید. در استقرار HTTPS مقدار `COOKIE_SECURE=1` شود. فایل `business_key.db` حاوی اطلاعات حساب‌هاست و باید دسترسی فایل و نسخه پشتیبان آن محدود باشد. کلید API فقط روی سرور نگهداری شود. در صورت افشای کلید، آن را فوراً از پنل ارائه‌دهنده باطل و جایگزین کنید.
